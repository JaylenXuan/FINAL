## P0

### 1. 「不进门就一定被抓」不成立——玩家按 Shift 就永远追不上

规格拍板④原话是「演示的人只要不进门，就一定会被抓」。按现在的数值算不出这个结果。

| 玩家状态 | 速度 | 与校长 3.6 的差 | 从 18.87m 追到贴身 |
|---|---|---|---|
| 站着不动 | 0 | — | **5.2 s** |
| 走路 | 3.2 | +0.4（校长快） | **47 s** |
| 跑步 | 6.0 | −2.4（玩家快） | **永远不会** |

- 证据：`src/player/player.js:3-4`（`WALK_SPEED = 3.2` / `RUN_SPEED = 6.0`）、`src/npc/chaser.js:5`（`CHASER_SPEED = 3.6`）；起点距离由 `src/bits/bits.js:122` 的 `farEnd` 决定，玩家在 `a_plaza (0,0,6)`、校长在 `(-10,-10)`，`√(10²+16²) = 18.87m`。
- 影响：**演示的结局由操作员的手指决定，不由规则决定**。会玩的人一慌就按 Shift，然后校长在他身后 10m 处匀速跟着走，一直跟到演示结束——这比被抓更难看。反过来，如果演示者老实不跑，他要在广场上走 47 秒才被抓，3-4 分钟的 demo 负担不起。
- 建议（三选一，都不改 schema）：
  - **A（最省事）**：`farEnd` 改成「固定 10-12m 的前方点」，别取对角。站着被抓 2.8-3.3 s，跑掉的人 5 秒内就甩开，两头都体面。
  - **B**：校长速度提到 6.4-7.0，让「跑不掉、只能进门」变成真的。代价：拍板④的 3.6 要改，且玩家会觉得自己被作弊。
  - **C**：保留 3.6，但给追逐加 8 秒上限，超时校长放弃并喊一句——把「跑得掉」变成设计而不是漏洞。
- 我的意见：**A + C**。A 让短距离成立，C 兜住「玩家真的跑了」的情况，两条都不动数值约定。

### 2. 校长会穿过教学楼出现——chaser 完全没有碰撞

- 证据：`src/npc/chaser.js:78-101` 的 `update` 只有「朝玩家直线位移 + bounds 夹取」，没有任何 `colliders` 查询。
- 具体路径：起点 `(-10,0,-10)`，目标 `(0,0,6)`；教学楼 `b_teach` 占 `x∈[-10,0], z∈[-9.8,-6.2]`（`data/world.json:6`，pos `[-5,0,-8]` + size `[10,16,3.6]` 的底面中心语义）。这条直线在 `z=-6.2` 处的 x 是 **−7.6**，正落在楼里 → **校长从后墙进去、从前墙穿出来，穿过 3.6m 厚的楼**。
- 影响：玩家在广场举手机，抬头看见校长从教学楼墙体里走出来。这是最容易被同学一句「他怎么穿墙」问倒的地方。
- 建议：`chaser.update` 里加一次 `resolve()`（`player.js:8` 那个圆 vs AABB 推出函数，直接 import 复用），成本 5 行，能挡住穿墙。更彻底的做法是刷点避开建筑（见第 3 条）。

### 3. 刷点取的是几何角点，不看那里有没有建筑

- 证据：`src/npc/chaser.js:53-76`，四个角就是 `bounds` 的四角，没有建筑、没有道具的排除。
- 现状：`bounds` 是 `[-10,-10]~[10,10]`，而教学楼后缘在 `z=-9.8` → 角点 `(-10,-10)` **离教学楼后墙只有 0.2m**。玩家在 `(0,6)`，`(-10,-10)` 和 `(10,-10)` 距离相同（都是 18.87m），代码取先找到的那个，于是永远选左后角。
- 影响：校长贴着楼后墙刷出，玩家在广场上看不见他；他先钻过楼（第 2 条），再从楼前出现。**「远处走来一个校长」这个镜头彻底没了**。
- 建议：刷点表改成数据驱动——在 `world.json` 的 `outdoor` 里加 `"spawns": [[x,z], ...]`（**这是改 schema，要走 CHANGELOG**）；或者先用最土的办法：`farEnd` 从「四个角」改成「圆周采样 16 个点，扔掉落在任何 building 里的，取最远」，不碰 schema。

### 4. 「进门 2 秒后放弃」玩家根本看不到——因为进门是瞬移

- 证据：`src/bits/bits.js:76-89` 的 `fleeTimer` 只在 `player.zone !== 'outdoor'` 时累加；而 `player.zone` 只在 `player.teleport()` 里改（`src/player/player.js:87`），`teleport` 只被 `main.js:88/124/149/156` 调用，全部是**按 E 交互或选点**的瞬间。
- 也就是说：玩家按 E 的那一刻，人已经飞到 `x=100` 的教室里了，黑屏 0.45s 淡入，抬头看到的是黑板。**那个 2 秒倒计时是在他已经看不见校长之后才走完的**。
- 影响：规则是对的，表现是空的。玩家学到的因果关系是「按 E = 安全」，而不是「跑进楼 = 校长放弃」。而且因为房间在 `x=100`，玩家物理上永远不可能「跑进楼」，这条规则在空间上不成立。
- 建议（二选一）：
  - **不改代码**：接受「按 E 即逃脱」，把 §9 的措辞从「进任意房间」改成「从门离开广场」，并在逃跑成功时给一句台词 + 让校长在门口停一下再消失（`despawn` 前插 0.4s 的转身）。
  - **改代码**：给门加一个 3m 的触发区，**走进去就自动 `goTo`**，这样「跑进楼」是真的在跑。代价是 `builder` 要给门产 triggering zone，属于接口改动，得先写变更说明。

## P1

### 5. `onCapture` 里写死了 `'phone_walk'`

- 证据：`src/bits/bits.js:30` — `this.chaser.onCapture = () => this.onCaught('phone_walk')`。
- 影响：现在只有一条追人 bit，看不出问题。**加保安追人（图书馆、食堂）的第一天就会踩**：保安抓到人，系统却去结算 `phone_walk` 的后果，星数和文案全错。
- 建议：`spawn` 时把 bitId 记在 chaser 上（`chaser.bitId = bit.id`），`onCapture` 里读回来。3 行。

### 6. 三星直接带走时，演出被整段跳过

- 证据：`src/bits/bits.js:111-117`，`addStar` 之后 `n >= 3` 直接 `emit('death')` 并 return，**没走 `ui.subtitle`、没走 `audio.alarm`、没走 `chaser.spawn`**。
- 对比第一次、第二次违规：有喊话字幕 + 警报 + 校长刷出；第三次什么都没有。
- 影响：玩家第三次举手机走满 4 秒，画面**毫无预兆地直接黑屏**。同一套操作三种反馈，第三次最突兀，而这恰好是 demo 里最想让人笑的一次。
- 顺带：`line` 仍取 `bit.outcome.line` = `PHONE_CAUGHT`（`"No phones while walking."`），但语义已经从「被抓」变成「三次了，跟我走」。**缺一条 `STAR_LIMIT` 文案**（归内容侧）。
- 建议：三星分支不要 return，改成「喊话 → 校长秒到玩家身边 → 立即抓」的短序列（0.6s），复用 `caught` 时间轴。改动只在 `bits.js` 一个函数内。

### 7. 从教室出来会落在广场正中央，不是门口

- 证据：`src/world/builder.js:197-204`，房间出口的 `anchorId` 写死 `'a_plaza'`；`a_plaza` 在 `(0,0,6)`（`data/world.json:19`），而教室的门在广场 `(-3,0,-6.2)`。两点相距 **12.5m**。
- 影响：玩家按 E 出门 → 黑屏 0.45s → 睁眼站在广场中间。玩家会以为自己被传送了，不是走出了门。**三个房间共用同一个出口锚点**，连廊出口也落在广场中心，空间关系完全断掉。
- 建议：给每个房间一个自己的「门外锚点」（数据侧加 `a_out_classroom` 等 3 个，**不改 schema，只加数据**），`builder` 的出口改成读 `room.exitAnchor || 'a_plaza'`（这是给 schema 加可选字段，需走 CHANGELOG；或先用 room.id 拼约定名，不动 schema）。

### 8. `death` 事件在非 Play 状态会被静默吞掉，但 `captured` 已经置真

- 证据：`src/main.js:108-115` 第一行 `if (!state.is(S.PLAY)) return`；而 `src/npc/chaser.js:103-106` 是先 `this.captured = true` 再回调。
- 影响：只要 `death` 在 `WAKEUP` / `CAUGHT` / `ANCHOR` 期间触发（重生那一瞬被追上、连按），事件被丢弃，**校长却站着不动了**（`captured=true` 让 `update` 直接 return），玩家恢复控制后身边杵着一个不动的校长，只能按 R 救场。
- 建议：`death` 处理里把守卫从「return」改成「排队」——非 PLAY 时记一个 `pendingDeath`，回到 PLAY 后立刻结算。

## P2

### 9. 室内没有影子（灯光侧，Partner 负责）

`sun.shadow.camera` 只覆盖原点 ±26（`src/main.js:55-60`），而三个房间在 `x=100/200/300`。室内物体全部在阴影相机之外 → **桌子、讲台、校长都没有影子**，靠 `AmbientLight 0.45` + 半球光硬撑。截图里能看，但一眼是「灰盒」。房间的灯要在 `world/builder` 里按 room 挂一套（一盏方向光 + 一盏点光，`castShadow` 只开其中一个），否则 W3 的正式布光会返工。

### 10. 性能红线没有测量入口

§10 定了「draw call < 150、三角面 < 15 万、1080p ≥ 55fps」，但代码里没有任何地方读 `renderer.info`。建议加 `?perf=1`：左上角显示 `calls / triangles / fps`，只在带参数时挂上去，10 行。不然 W3 冻结那天没东西可打。

### 11. `?screen=anchors` 在 Play 状态下按 Enter 无效

`src/main.js:168-170` 直接 `showPicker(..., () => {})`，但 `state` 还是 `PLAY`，而 Enter 只在 `ANCHOR` 状态处理（`main.js:204-213`）→ 调试界面卡住，只能刷新。改成 `state.set(S.ANCHOR)` 再开 picker，一行。

### 12. `input.once()` 不消费按键——同一个键被两处读会同时响应

`src/player/input.js:30-32` 的 `once()` 只做 `pressed.has(code)`，不清除；`endFrame()` 统一清。现在没炸，是因为 `readKeys` 在 `bits.questionOpen` 时整段 return（`main.js:184`），答题键只被 `bits.readAnswer` 读到。**但这是隐式依赖**：以后任何一处想「独占」某个键，都必须再补一个 if。要么改成 `consume(code)`（读时清除），要么在 `input.js` 顶部注释写明「once 是查询不是消费，冲突自己躲」。
